# dsh-task-suite 升级后重打补丁指南

> DSH 升级（如 rc.6 → rc.7）会覆盖全局安装的 SDK；本套件是 **profile 插件**，
> 不修改 DSH 安装包，因此升级本身不破坏它。需要做的只是**重新构建/校验**，
> 并在必要时**对齐新 SDK 的 peer 版本**。皮肤中心宿主等 host 端插件在 DSH
> 升级后通常无需改动（基于公开 SDK API）。

## 1. 升级后立即做

```bash
# 1) 确认本套件还能构建
bash dsh-task-suite/build.sh

# 2) 对照新 DSH 版本的 SDK peer 版本（套件各包的 devDependencies）
node -e "const p=require('$(pwd)/dsh-task-suite/package.json'); console.log(p.devDependencies)"
# 若新 DSH 的 @deepseek-ai/* 版本不是 0.1.0-rc.6，更新：
#   - pnpm-workspace.yaml 的 minimumReleaseAgeExclude 列表
#   - 各包 devDependencies 里的 @deepseek-ai/* 版本号
# 然后重跑 pnpm install && build.sh

# 3) 跑一遍测试与静态校验
cd dsh-task-suite && pnpm -r typecheck && pnpm -r test
node scripts/aggregate.mjs --check && node scripts/skin-center-bundles --check
```

## 2. 重新打包测试（test-env，3090）

```bash
scripts/test-env-reset.sh                              # 恢复官方基线
# 填 test-envs/test-env-N/USAGE.md 声明（TEST_ENV_INDEX 选择）
bash dsh-task-suite/install-to-test-env.sh             # 装套件（默认启用 maid-atelier）
scripts/test-env-stop.sh && scripts/test-env-start.sh
bash dsh-task-suite/verify.sh --live                   # boot 清单 + bundle 路由 + 日志
# 皮肤热切换抽查（apply whale-song → 回来）
curl -s -X POST http://127.0.0.1:3090/api/skin-center/apply -H 'Content-Type: application/json' -d '{"skin":"whale-song"}'
# 测试完成后恢复
scripts/test-env-stop.sh && scripts/test-env-reset.sh
```

## 3. DSH 破坏性更新的应对

| 现象 | 原因 | 应对 |
|---|---|---|
| host 插件 apply 报 inject 服务缺失 | 新 DSH 改了服务名/依赖图 | 更新 skin-center/git-graph/aionui-panel 的 `inject` 声明（对照新 SDK） |
| client bundle 挂载后无 UI | 新 shell 布局选择器变了 | compat shim（聚合包 src/client）的 `data-pane` 选择器可能失效；按新 shell DOM 更新 `COLUMN_SHIMS` |
| skin-switch 找不到 profile | DSH_HOME 解析逻辑变化 | 检查 `packages/skins/skin-center/src/skin-switch.ts` 的 `resolveHarnessHome` 各优先级 |
| 上游 dsh-web-ui 发新版 | 有修复/新功能 | 按本 README §1 重新拉取 vX.Y.Z，把对应包源码拷入并重跑 rebrand 检查（grep @linxin666） |
