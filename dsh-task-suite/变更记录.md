3. **新增皮肤**：收录 dsh-deep-whale 的 `maid-atelier`（深海女仆工坊）：
   包名改 `@zzyyyds88/dsh-client-ui-skin-maid-atelier`，版本对齐 0.1.17，

4. **聚合包**：`dsh-web-ui-all` → `dsh-task-suite-all`，aggregate.yml 裁剪为
   6 个 patchFrom + 7 个 deps（去掉 pet/ssh/remote/liangshen/describe-image），
   `scripts/aggregate.mjs` 重生成 cordis.patch.yml 与 dependencies。
5. **allowlist 裁剪**：web-ui-settings 的 `FAMILY_NAMESPACES` /
   `NAMESPACE_ALIASES` 去掉已抽取外的命名空间，加 `dsh-task-suite-all` 别名；
   同步修 allowlist.spec.ts / bridge.spec.ts 断言。
6. **工程化**：build.sh（顺序构建）、install-suite-plugin.mjs +
   install-to-test-env.sh（幂等安装）、verify.sh（静态 + --live 黑盒）、
   README / 本文件 / 升级指南。

### 为什么

- 用户要求把 dsh-web-ui 的部分功能放进自己仓库、组成一个插件，并加皮肤设置
  与 deep-whale 皮肤；scope 改为自己的 `@zzyyyds88`。
- 本机正式 profile 曾因 v0.1.16 的 `fallbackStarted` TDZ 停用这几个插件；
  v0.1.17 已修复，故直接抽取最新版。

### 怎么验证

- `pnpm -r build`：21 包构建成功；`aggregate.mjs --check`、`skin-center-bundles --check` 通过。
- `pnpm -r typecheck` 通过；`pnpm -r test` 全绿（690+ 断言；期间修复
  web-ui-settings 2 个测试文件与 maid-atelier 的 peerDependencies 断言）。
- test-env（3090）安装 + 启动：boot 清单含 7 个插件 + maid-atelier 皮肤；
  8 个 client bundle 路由 200；日志无错误。
- 皮肤热切换闭环：apply whale-song → maid-atelier → official → maid-atelier，
  boot 每次跟随，无 duplicate entry id、无 TDZ。

### 踩坑记录（重要）

- **profile 层不能写皮肤 insert 行**：最初安装器把 `ui-skin-<id>` 行写进
  profile 的 cordis.patch.yml，而皮肤中心宿主把 managed 区段写进 HOME 层
  cordis.patch.yml —— 同一 id 两处 insert → 重启时
  `duplicate loader entry id: ui-skin-maid-atelier` 启动失败（热更新时旧图
  形残留导致 boot 不跟随）。修复：profile 层只写聚合 7 行；皮肤互斥只由
  HOME 层 managed 区段管（与上游 dsh-skin / skin-switch 语义一致）。
- **基线空 patch 是「注释 + []」文档**：安装器追加行前必须剥注释识别空
  文档，否则 YAML 报 "end of the stream or a document separator is expected"。
- **运行时第三方依赖**（schemastery / zod）不在 profile node_modules 时，
  host 插件 import 失败（`Cannot find package 'schemastery'`）：
  `pnpm add schemastery@^3.18.0 zod@^4.4.3` 装进测试 profile（hoisted 布局，
  与官方 profile 一致）；`@deepseek-ai/*` 由 loader 从全局安装回退解析，无需装。
- **测试环境被并发会话污染**：共享 test-env 曾被另一会话重新装入访问门禁
  fork 与 patch 行（node_modules mtime 与 patch 内容异常）。处理：清理残留、
  重写干净 patch 后继续；测试完成后恢复官方基线。

### 怎么回退

- 未提交前：`git checkout -- dsh-task-suite`（或删除整个文件夹）。
- 测试环境：`scripts/test-env-stop.sh && scripts/test-env-reset.sh` 回官方基线；
  patch 还原见 `test-env/profiles/web/cordis.patch.yml.bak`。
