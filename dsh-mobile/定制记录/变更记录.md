## 一、做了什么（v0.1 → v0.2.0）

原工作区已有一个宿主侧 `dsh-mobile-adapt`（tapIndex 注入 CSS，选择器
多为猜测，对真实 DOM 基本无效），且随正式 profile 已部署。本次在
`dsh-mobile/` 立项重做并升级为 0.2.0：

1. **宿主插件（lib/index.js）重写**：保留 tapIndex CSS 注入架构；删除
   失效/猜测选择器（`data-chat-flow`、`data-message`、`data-tooltip`
   在 rc.6 DOM 中不存在）与遗留的 `/diag` 调试路由；CSS 全部按实测
   DOM 重写并限定 `@media (max-width: 768px)`。
2. **新增浏览器端 bundle（lib/client.js）**：`dsh.client` 声明 + 手写
   `__ModuleLoader__` bundle，负责窄屏布局（见下），改完浏览器刷新即生效。
3. **修复内容**（全部为窄屏媒体查询内的 CSS + 一个 data 属性）：
   - 聊天区解放：aionui 文件树/预览列从 grid 轨道变右侧抽屉，聊天区
     114px → 334px（390 视口实测）；
   - 抽屉默认收起 + root 切换自动收起 + 用户点浮出按钮放行；
   - 设置弹层加宽（`calc(100vw - 16px)`）、字段行纵向堆叠，消除文字
     逐字竖排；
   - 输入框 16px 防 iOS 聚焦缩放 + safe-area 底部留白；
   - 桌宠缩小贴角、弹层打开时让位（`:has`）；
   - 禁 `overscroll-behavior-y` 下拉刷新干扰。

## 二、为什么（根因）

| 现象 | 根因 |
|---|---|
| 聊天区 114px | `dsh-aionui-panel` 把 220px 文件树作为 grid 轨道写入 AppFrame inline grid；其 clamp 下限 220px，窄容器不收缩 |
| 设置文字竖排 | 设置弹层右侧内容区仅 154-278px，字段行横排被挤爆 |
| 输入聚焦页面放大 | iOS 对 <16px 输入框自动缩放 |
| 桌宠遮挡 | 桌宠绝对定位右下角 z-30，高于部分弹层 |

## 三、怎么验证（test-env-1，端口 3090）

1. `bash build.sh` + `bash install-to-test-env.sh` + 重启测试实例；
2. `bash verify.sh` / `bash verify.sh --live` 全绿；
3. Playwright 390×844 移动视口实测（截图 + DOM 断言）：
   - 聊天区宽度 106px → 326px，`data-dshm-narrow` 已加，grid 为
     `56px minmax(0,1fr) 0 0 0`，无横向溢出（scrollW=390）；
   - 文件树抽屉：启动自动收起（visibility hidden、x=404 屏外）→ 点浮出
     按钮滑入（x=46）→ 点收起箭头滑出（x=404）；
   - 设置弹层 374px 全宽、导航 64px 图标栏、内容区 310px、无竖排坏字；
   - 用户主动打开抽屉不被自动收起（capture 委托区分用户操作）。
4. 识图模型（dots3-note-prev）复核截图：主界面「正常且美观、无截断/
   重叠/溢出」；设置面板文字排版正常（仅桌宠遮挡一处，已由 :has 规则
   修复）。

## 四、怎么回退

- **test-env**：`test-envs/test-env-1/profiles/web/node_modules/dsh-mobile-adapt.bak`
  为旧版备份，拷回 `node_modules/dsh-mobile-adapt` 再重启。
- **正式**：`install-to-profile.sh` 安装前自动备份到
  `profiles/web/node_modules/dsh-mobile-adapt.bak`；回退 = 拷回 .bak 重启。
