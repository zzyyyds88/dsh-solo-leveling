# dsh-mobile-adapt 升级后重打补丁指南

> 场景：DSH 升级/重装后，`dsh-mobile-adapt` 插件可能失效或需要重装。
> 本插件是 **profile 挂载插件**（`cordis.patch.yml` 条目 + profile
> node_modules 内包），不修改安装包，**升级天然免疫**——只需重复安装命令。

## 1. 先判断是否失效

```bash
# 检查 patch 条目还在不在（DSH 升级一般不动 profile，但保险起见）：
grep -A3 'mobile-adapt' /root/.dsh/profiles/web/cordis.patch.yml

# 检查包是否在位：
ls /root/.dsh/profiles/web/node_modules/dsh-mobile-adapt/lib/

# 浏览器手机视口（≤768px）打开 GUI：聊天区应占满全宽；
# 右侧应有浮出按钮（文件树抽屉入口）。
```

## 2. 重打步骤（幂等，重复执行安全）

```bash
cd <本仓库>/dsh-mobile
bash build.sh                                  # 如改过 src/ 才需要
bash install-to-profile.sh                     # 自动备份旧包 .bak 并重启正式 dsh web
# 或只换文件不重启：
bash install-to-profile.sh --no-restart && <手动重启 dsh web>
```

## 3. 为什么本插件升级免疫

- 不碰 `/usr/lib/node_modules/@deepseek-ai/dsh` 安装包；
- 宿主侧只依赖 `ctx.webServer.tapIndex`（DSH 稳定 API）；
- client bundle 走官方 `__ModuleLoader__` 协议 + `dsh.client` 声明，
  `dsh-client-modules` 每次启动自动扫描 profile 内已装包的声明并入启动图；
- 若 DSH 大版本改变 client bundle 协议（`__ModuleLoader__` 格式），
  参照同仓库 `dsh-client-ui-access-gate` 的手写格式同步更新
  `src/client.js` 后重建即可。

## 4. 依赖插件

- 抽屉逻辑针对 `dsh-aionui-panel`（dsh-task-suite 的右侧面板）。若
  未安装该插件，本插件仅剩设置面板/输入区/桌宠等通用适配，无副作用。
- 桌宠规则针对 `deepseek-pet`；未安装时相应规则不匹配，无副作用。
