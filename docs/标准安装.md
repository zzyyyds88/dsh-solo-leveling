# 标准插件包安装（dsh plugin add）

> 2026-08-16 起，本工作区全部自研/收录插件均为**标准插件包**：
> `package.json` 声明 `dsh.bundle.patch`（指向包内 `cordis.patch.yml` 挂载清单），
> DSH loader 按 profile 的 `dsh.profile.bundles` 自动读取包内 patch 挂载，
> **不再需要安装脚本写用户层 patch**。安装 = `dsh plugin --profile web add <包>`。

## 标准插件包结构

```jsonc
{
  "name": "dsh-xxx",
  "version": "0.1.0",
  "private": false,
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },  // 挂载清单（insert 行 + config 表达式）
    "client": { "platform": "web", "inject": [...] }  // 前端插件：client bundle 进启动图
  },
  "files": ["lib", "cordis.patch.yml", "assets"]  // npm pack 白名单（必须含 lib/）
}
```

包内 `cordis.patch.yml` 示例（可含 `!!js` 表达式 config）：

```yaml
- insert:
    - id: access-gate
      name: dsh-host-access-gate
      inject:
        - webServer
      config:
        password: !!js process.env.DSH_ACCESS_GATE_PASSWORD ?? process.env.DSH_WEB_PASSWORD
        mode: 'on'
```

## 安装命令

```bash
# 1) 打包（lib/ 与 cordis.patch.yml 必须进 tgz，npm pack 前先构建）
cd <包目录> && npm pack            # → <name>-<version>.tgz

# 2) 标准安装（DSH_HOME 指向目标环境；profile 名通常 web）
DSH_HOME=<目标 DSH_HOME> dsh plugin --profile web add ./<name>-<version>.tgz

# 3) 重启生效（后端插件）
scripts/test-env-stop.sh && scripts/test-env-start.sh
```

`dsh plugin add` 做的事：pnpm 装包进 profile node_modules + 把带 `dsh.bundle.patch`
的包写进 profile `package.json` 的 `dsh.profile.bundles`（`reconcilePlugins`）。
启动时 loader 按 bundles 顺序应用每个包的 patch 层 —— **用户层
`cordis.patch.yml` 全程不动**。

## 卸载 / 升级

```bash
dsh plugin --profile web remove <包名>    # 卸载（dependencies + bundles 一并清理）
dsh plugin --profile web add ./<新版本>.tgz  # 升级（pnpm 覆盖为最新）
```

## 注意事项

- **不要再手工向用户层 `cordis.patch.yml` 写插件 insert 行**：标准安装下挂载在
  bundle 层，用户层残留行会 `duplicate loader entry id` 启动崩溃。
- 子包未发布 npm registry：task-suite 全家安装必须本地 `pnpm -r pack` + 依赖改写
  `file:` 路径（`install-suite-plugin.mjs` 已封装），或未来发布 `@zzyyyds88/*` 到 npm。
- fork 插件（@deepseek-ai/* 同包名覆盖）是唯一保持「拷目录」方式的部分
  （CLI 会拉官方 npm 版，装不了本地 fork）。
