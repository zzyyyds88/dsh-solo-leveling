# 手机遥控插件设计（dsh-host-mobile-remote + dsh-client-ui-mobile-remote）

> 状态：已实现（2026-08-23）。实现落点 `packages/host/mobile-remote`、
> `packages/client/ui-mobile-remote`；与设计的契约差异见文末「回写实况」。
> 配套文档：[任务看板host化.md](任务看板host化.md)（定时模块的数据源）、
> App 侧设计 `DSH Reins/docs/design/dsh-remote-android-设计文档.md` 与技术文档（同级 `DSH Reins` 工作区）。
> 本文件是手机遥控插件（App 与 dsh 之间的 BFF 层）的**唯一技术事实源**。

## 1. 定位

DSH 遥控器（安卓 App，Flutter 瘦客户端）与 dsh Host 之间的专用后端插件：

- 对 App 暴露**小而稳定**的 HTTP + WebSocket 契约（`/api/mobile/*`）；
- 对内进程内调用 `ctx.apiProxy` / `ctx.taskBoard` / `workspaceRegistry`，不发明业务逻辑；
- 不持有业务状态（会话、任务真相都在各域服务）。

## 2. 为什么需要 BFF（App 不直连 `/api` 的原因）

1. **信任围栏**：connection 对 `/api` 有 `isTrustedApiRequest`
   （`packages/client/connection/src/api-request-trust.ts`）：Host 头必须是 loopback 或
   `--trusted-host` 名单 + Origin/sec-fetch 校验。App 走内网穿透域名会被拒，
   除非用户加启动参数——把内网穿透域名写死进启动配置不可维护。
2. **协议面**：`/api` 全量 52 个方法、四象限 RPC 信封、特权方法围栏，App 直接消费
   则上游任何协议变动都砸到 App 发版。
3. **鉴权**：access-gate 只有口令 + Cookie，无 Bearer 途径；App 直连无增益。

mobile 插件走 webserver 自有前缀路由（最长前缀匹配优先于 connection 的 `/api`，
skin-center 先例），天然绕开 1；白名单解决 2；复用门禁解决 3。

## 4. 端点契约（protocolVersion = 1）

统一错误体：`{"ok":false,"error":{"code":"...","message":"..."}}`；
成功体：`{"ok":true,"value":...}`（对齐 apiproxy 的 `RpcResult` 形状）。
除 `GET /api/mobile/info` 与 WS 外全部 `POST` + `application/json`。
请求体上限默认 20MiB（可调，见 §10）。

| # | 端点 | 请求 | 响应 / 说明 |
|---|---|---|---|
| 1 | `GET /api/mobile/info` | — | `{protocolVersion:1, pluginVersion, hostVersion, serverTime}`；App 连接时首先校验 protocolVersion |
| 2 | `POST /api/mobile/rpc` | `{method, payload}` | 白名单内方法进程内转发；见 §5 |
| 3 | `POST /api/mobile/respond` | `{rpcId, kind:'approval'\|'question', result}` | 包装成 `ClientResponse` 调 `apiProxy.respond`；approval 的 `result` = `ApprovalOutcome`（`'allowed-once'\|'rejected'\|'cancelled'\|'unavailable'`，`packages/interaction/user-approval/src/types.ts`）；question 的 `result` 结构实现时对照 `AskUserQuestion` 应答 schema 定稿 |
| 4 | `POST /api/mobile/fs/read` | `{workspaceId, path, asImage?}` | 产物读取：文本 ≤80k 字符；图片转 dataURL ≤8MiB；路径限制在 workspace 根内（防穿越，仿 aionui-panel `FsService`） |
| 5 | `GET /api/mobile/fs/raw` | `?ws=<workspaceId>&path=<...>`，支持 `Range` | 原始字节流（大文件/下载） |
| 6 | WS 升级 `/api/mobile/events` | — | 下行事件流，见 §6 |

错误码（App 端映射中文文案）：`method-not-allowed`（白名单外）、`bad-request`、
`unauthorized`（门禁 401 透传）、`not-found`、`payload-too-large`、`internal`。

## 5. RPC 白名单 v1

`POST /api/mobile/rpc {method, payload}` 的 `method` 只允许下表；
超出即 `method-not-allowed`。转发实现 = 进程内调用 `ctx.apiProxy` 对应 face
（`.sessions` / `.llm` / `.host`，签名见 `packages/host/apiproxy/src/api/`），
或 `ctx.taskBoard`（task-board host 半，见配套文档；未装配时该组方法从白名单剔除）。

| 组 | 方法 |
|---|---|
| host | `host.describe` |
| session | `session.list` `session.create` `session.history` `session.prompt` `session.cancel` `session.fork` `session.rename` `session.models` `session.selectModel` `session.attachment` |
| llm | `llm.providers` `llm.models` |
| workspace | `workspace.list` |
| task-board | `task-board.list` `task-board.create` `task-board.update` `task-board.delete` `task-board.run` |

白名单扩项 = 插件版本变更（+patch）；缩项/改义 = protocolVersion 递增。

## 6. 事件流（`/api/mobile/events`）

- **单条下行 WebSocket**（`ctx.webServer.registerUpgrade`，`ws` noServer 模式，
  参照 `packages/client/connection/src/websocket-downlink.ts`）：App 只养一根连接。
- 客户端上行任何消息 = 协议违规，`close(1008, 'downlink only')`（上行全走 HTTP POST）。
- 帧：`{"stream":"mux"|"host"|"taskboard"|"meta","frame":{...}}`：
  - `mux` = apiproxy `MuxFrame` 原样透传（`session/subscribed` 基线、`session/event`、
    `approval/requested|resolved`、`question/requested|resolved`、`session/queue`、
    `session/jobs`、`session/projection`、`stream/error`）；
  - `host` = `HostFrame` 原样透传（`host/session-added|removed|status|agent-error`、
    `host/workspace-*` 等）；
  - `taskboard` = `{type:'task-board/changed', tasks}` 全量快照（订阅 cordis 事件）；
  - `meta` = 连接建立时先发 `{type:'mobile/hello', protocolVersion, serverTime}`。
- 每条 App WS 连接独立消费 `apiProxy.events.mux` / `.events.host` 迭代器（与官方 downlink 同构）；
  服务端 15s ws ping 心跳。
- **断线恢复**：mux 的 `since` 参数官方 v1 未实现，App 端策略 = 重开 WS + 对活跃会话
  `session.history` 拉尾页 + 按 `seq` 去重/找洞缝合（官方客户端同款，App 文档已写）。
  pending 的 approval/question 帧由 host 在流重开时按稳定 rpcId 重放，App 不丢待办。

## 7. 鉴权（复用 access-gate，零改动）

- 插件全部路由处于门禁之后（gate 全局前置），**不自建鉴权**。
- App 登录契约（源码核对，`packages/host/access-gate/src/index.ts`）：
  - `POST /login`，`content-type: application/json`，体 `{"password":"<门禁口令>"}`；
  - 成功 = **302** + `Location: /` + `Set-Cookie: dsh_session_<port>=v1.<exp>.<nonce>.<hmac>; Path=/; HttpOnly; SameSite=Strict; Max-Age=604800`；
  - 失败 = 302 + `Location: /login?error=wrong`；锁定 = `?error=locked`
    （默认 10 次失败 / 10 分钟窗口，按来源 IP）；
  - Cookie 名含监听端口（默认 `dsh_session_3080`），App 直接回存 `Set-Cookie` 串即可，无需解析；
  - 之后所有 HTTP 请求与 **WS 升级请求**都带该 Cookie（Dart `IOWebSocketChannel` 支持自定义 headers）；
  - 401 / Cookie 过期 → App 用安全存储中的口令自动重登。
- 明文 HTTP 拒连（App 侧校验 `https://` 前缀）；自签证书由 App 端 TOFU 指纹校验兜底。

## 8. 版本与兼容

- `protocolVersion` 常量随契约破坏性变更递增；`/api/mobile/info` 上报，App 不匹配弹告警。
- 白名单方法缺失（如旧 host 无 `task-board.*`）→ 该方法报 `method-not-allowed`，
  App 按能力降级（隐藏定时模块入口）。

## 9. 依赖注入面与实现要点

- host 半 `static inject = ['webServer', 'apiProxy', 'workspaceRegistry']`，
  `taskBoard` 为可选依赖（`inject: ['taskBoard']` + 容缺失降级，白名单动态裁剪）。
- 路由注册仿 `ui-skin-center/src/index.ts`（失败回滚包装）；
  `ctx.effect(() => ctx.webServer.register(...), 'mobile-remote: routes')`。
- fs 读取自实现（node fs + workspaceRegistry 圈根 + 防穿越 + 上限），
  不注入 agent 世界 的 `fs` 域。
- 不经过 `toFetchHandler` HTTP 回环；直接进程内调 `ctx.apiProxy` 方法，
  信封由插件自己按 `RpcResult` 形状包（`{ok,value|error}`）。

## 10. 配置卡（红线 5）

命名空间 `mobile-remote`，schema：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | boolean | `true` | 总开关：false 时全部 `/api/mobile/*` 回 404，WS 拒升级 |

## 12. 验收口径

1. `pnpm run build` 全绿；打包 → 全局安装 → `dsh web`。
2. 未登录访问 `/api/mobile/info` 得 401；`POST /login` 拿 Cookie 后全链路可用。
3. curl 模拟：`/api/mobile/rpc` 调 `host.describe`/`session.list` 成功；
   白名单外方法得 `method-not-allowed`。
4. wscat 带 Cookie 连 `/api/mobile/events`：先收 `mobile/hello`，随后
   `session/subscribed` 基线与实时 `session/event` 帧；发上行消息被 1008 关闭。
5. `task-board.*` 增删改查 + `taskboard` 变更帧（依赖看板 host 化完成）。
6. 设置卡「手机遥控」总开关关闭后路由 404、WS 拒升级；请求体超限回 413 语义错误体。

## 13. 回写实况（实现期与设计稿的契约差异，以本节为准）

实现过程中对照源码定稿了以下契约细节；未列出的条目以 §4–§11 为准。

### 13.1 respond 的 result 定稿（§4 端点 3）

`result` 即 apiproxy `ClientResponse.result.value` 槽的 payload，按 kind 分派：

- `kind:'approval'` → `{sessionId, approvalId, outcome}`，其中 `outcome`
  只接受 `'allowed-once' | 'rejected'`（`cancelled/unavailable` 是 host 侧
  结算结果，客户端不可给，见 apiproxy `approvals.ts`）。`respond()` 会校验
  sessionId/approvalId 与 rpcId 路由到的 pending 记录一致。
- `kind:'question'` → `{sessionId, answer:{answers:[{id, selected:string[],
  custom?}]}}`（对照 `questions.schema.ts` 的 zod 定义）。

应答成功返回 `{ok:true,value:{accepted:true}}`；receipt `not-pending` 映射
`not-found`，`bad-response` 映射 `bad-request`。

### 13.2 WS 帧信封补 rpcId（§6）

mux/host 流的应答帧（approval/question requested）必须携带 server-request 的
rpcId 才能回答，而 MuxFrame 本身不含该 id。信封定为
`{"stream":"mux"|"host"|"taskboard"|"meta","frame":{...},"rpcId?":"..."}`——
mux/host 帧附带迭代器给出的 rpcId（answerable 帧为稳定逻辑 id），meta/taskboard
帧不带。连接建立只发 `mobile/hello` 一帧；taskboard 全量快照由 App 在连接后用
`task-board.list` 自取基线，之后随 cordis `task-board/changed` 单订阅扇出。

### 13.3 错误码折叠规则（§4）

上游（apiproxy RpcError、BoardError）错误码凡属于闭集
`method-not-allowed|bad-request|unauthorized|not-found|payload-too-large|internal`
的原样透传，其余一律折叠为 `internal`，message 保留原文。HTTP 状态映射：
400/401/403/404/413/500；非 JSON Content-Type 的 POST 按 `bad-request` 回 400；
已知路径方法不对时回裸 405（载体层语义，不在信封闭集内）。

### 13.4 其他落点

- 白名单转发 = 进程内直调 face（不经 toFetchHandler 回环）；payload 不做
  二次 schema 校验，原样交给上游域服务（与官方 carrier 同责）。
- `enabled=false` 时 HTTP 全部回 404 信封体；WS 升级直接以裸
  `HTTP/1.1 404` 应答后断开。
- 设置读取为每请求/每升级即时读（installSettingsSection + onChange 重算），
  保存即生效；`maxRequestBytes` 同时约束 POST 体上限。
- fs 读取自实现 node:fs 圈根（workspaceRegistry id → 根目录，
  join + 大小写不敏感前缀检查 + realpath 祖先链防符号链接逃逸），
  文本截断 80k 字符、图片 dataURL ≤8MiB、`.git` 无特殊限制（只读面）。
