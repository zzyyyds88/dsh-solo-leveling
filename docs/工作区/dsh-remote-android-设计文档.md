## 1. 项目概述

### 1.1 一句话定位

**dsh 的安卓手机遥控器**：手机下发任务、追踪进度、接收通知、预览产物，Agent 全程在 PC 端的 dsh（DeepSeek Harness）运行时中执行。

### 1.2 背景

- 用户在本机运行开源 Agent 框架 **dsh**（DeepSeek Harness，Cordis 插件架构，Web UI 默认端口 3080），已能通过浏览器完成任务的查看与下发。
- 使用中发现 dsh 官方 Web UI 存在交互与体验上的不足，希望获得像 Trae（字节跳动 AI IDE 移动端）那样顺手的移动端体验。
- 用户长期不在电脑前（通勤、出差），需要**手机随时调度 PC 上的 Agent** 干活。

### 1.3 对标参照

| 维度 | Trae 移动端 | 本项目（DSH 遥控器） |
|---|---|---|
| 架构 | 瘦客户端 → 云端/PC Agent | 瘦客户端 → PC dsh Agent |
| 账号体系 | 手机号登录、多账号、多设备 | **无账号，单用户，本地持久化密钥** |
| 设备配对 | 同账号自动检测、多设备 | 无，配置穿透地址即可 |
| 工作模式 | Code + MTC 双模式 | **单模式**（dsh 本身是通用 Agent，不做模式区分） |
| 运行环境 | 云端沙箱 + 本地 PC | **仅 PC dsh**（无云端） |
| 语音输入 | 有 | **不做**（后续可按需扩展） |
| 定时任务 | 有 | 有（任务看板 host 化，网页/手机共用台账） |
| 推送通知 | 有 | 有（自建长连推送） |
| 产物预览 | 文档/代码/Web | 文档/代码/Web |

## 2. 设计目标与非目标

### 2.1 目标

1. **任务随时下发**：手机一条指令，PC dsh 立刻开始执行。
2. **过程可视**：实时看到 AI 的思考、工具调用、子步骤进度（Trae 式"对话式执行体验"）。
3. **产物可预览**：在手机上直接查看生成的文档、代码、Web 页面。
4. **后台可控**：定时任务 + 关键节点推送，App 在后台也能收到任务完成通知。
5. **单用户极简**：无注册、无多账号、无设备管理，安装即用。
6. **零业务状态**：手机端只做视图与缓存，唯一真相源在 PC dsh。

### 2.2 非目标

- ❌ 手机本地跑 Agent / 本地调模型 API。
- ❌ 多账户、多设备、账号体系。
- ❌ 语音输入、实时语音对话（列为未来扩展项）。
- ❌ Code/MTC 双模式入口。
- ❌ 云端沙箱环境。
- ❌ 在手机上浏览/编辑 PC 文件目录（仅在任务上下文中选择工作区）。

## 3. 用户与使用场景

### 3.1 用户画像

- 单用户，本人使用，非公开产品。
- PC 常开或可远程唤醒，dsh 运行在 Windows 上。
- 已具备内网穿透工具使用经验，习惯"手机 App 通过公网域名访问家中/办公 PC 服务"的模式。

### 3.2 核心使用场景

| 场景 | 描述 |
|---|---|
| 通勤下发任务 | 地铁上发指令"帮我总结今天代码改动写日报"，到家看成品 |
| 定时自动化 | 每天 09:00 定时让 dsh 扫描昨日提交生成日报，完成推送到手机 |
| 出差调度 | 出差期间手机下发任务到家中 PC，PC 执行后产物回传预览 |
| 碎片时间收尾 | 出门前启动长任务，路上看进度，回来直接收尾 |

## 4. 总体架构

### 4.1 架构图

```
┌──────────────────┐   HTTPS（内网穿透隧道）   ┌──────────────────────────────────┐
│  安卓 App         │ ───────────────────────► │  PC：dsh Host（:3080，门禁+TLS） │
│  (Flutter 瘦客户端)│    /api/mobile/* REST     │  ┌────────────────────────────┐  │
│                   │    + /api/mobile/events   │  │ 手机遥控插件（BFF）          │  │
│                   │    （下行 WS，单连接）     │  │ 白名单 RPC / 事件转发 /     │  │
│                   │ ◄───────────────────────  │  │ 产物读取                    │  │
│                   │                           │  └───────────┬────────────────┘  │
│                   │                           │              │ 进程内调用        │
│                   │                           │  agent / session / llm /      │
│                   │                           │  workspace / task-board / …   │
└──────────────────┘                           └──────────────────────────────────┘
        │
        │ 本地通知（App 内）
        ▼
  状态栏通知
```

### 4.2 四层职责

| 层 | 职责 | 说明 |
|---|---|---|
| **安卓 App（本项目建设）** | 纯 UI + 通信客户端 | 不跑模型、不含 Agent 逻辑；输入采集、事件流渲染、审批应答、产物展示、定时任务管理 UI、本地通知 |
| **内网穿透隧道** | 暴露 PC 3080 端口为公网 HTTPS 域名 | 复用用户现有内网穿透工具；App 内仅需配置域名 |
| **手机遥控插件（dsh 侧新增，`dsh-host-mobile-remote`）** | App 专属 BFF | 小而稳的 `/api/mobile/*` 契约 + 事件流转发；进程内调 dsh 各域服务；不含业务状态 |
| **PC dsh（已有，核心不动）** | Agent 运行时 | 模型调用、工具执行、沙箱、会话持久化、任务看板 host 化后的定时调度 |

### 4.3 核心设计原则

1. **瘦客户端**：手机端不保存业务状态，只缓存展示数据；断线重连后从 dsh 拉取补齐。
2. **经 BFF 访问，契约稳定**：App 只对话手机遥控插件的 `/api/mobile/*` 契约
   （protocolVersion 管理），不直连 dsh 原生 `/api`；上游协议变动由插件吸收。
3. **单用户安全**：门禁口令换 Cookie 会话 + 强制 HTTPS + 证书 TOFU 校验三重防线。
4. **本地存储仅缓存**：配置、会话摘要、定时任务镜像，全部可安全删除。

## 5. 架构决策记录（ADR）

| 编号 | 决策 | 理由 | 备选（放弃原因） |
|---|---|---|---|
| ADR-1 | **纯遥控器架构**（Agent 在 PC 跑） | dsh 完整能力（沙箱/文件/shell/schedule）无法在手机复刻；复用现有运行时成本最低 | 手机本地轻量 Agent（能力弱、需维护两套执行逻辑）；混合架构（开发量大） |
| ADR-2 | **Flutter** 开发安卓端 | 单代码库、UI 顺手、Markdown/代码高亮生态成熟、后续可顺带出 iOS | 原生 Kotlin+Compose（单平台、周期长）；WebView 套壳（体验受限）；RN（原生模块桥接繁琐） |
| ADR-3 | **内网穿透**连接 PC dsh | 用户已有内网穿透工具与使用习惯，外网可用，无需注册第三方账号 | 局域网直连（仅限在家）；Tailscale/ZeroTier（需装客户端+注册）；后续可在设置中支持多连接方式 |
| ADR-4 | **单模式**（不做 Code/MTC 区分） | dsh 是通用 Agent，单入口即可满足所有任务类型；减少无意义 UI 分支 | 双模式（纯 UI 区分，无实质收益） |
| ADR-5 | **自建长连推送**（下行 WebSocket + 本地通知） | 1 对 1 场景，不依赖厂商通道；避免国内安卓 FCM 需 GMS 的坑 | FCM（国内安卓通道问题多）；前台轮询（后台场景收不到通知） |
| ADR-6 | **口令换 Cookie 会话**（复用 dsh 访问门禁）~~Bearer Token 鉴权~~（v2 修订） | 源码核对：门禁只有口令 + HMAC 签名 Cookie（TTL 7 天），无 Bearer 途径；复用则零改动、自带限速与 HTTPS，App 存口令自动重登即可 | 独立 Bearer Token（需扩门禁或绕门禁，新增鉴权面）；无鉴权（穿透域名暴露有风险） |
| ADR-7 | **dsh 核心不动，以第一方插件形式追加**（v2 修订：新增手机遥控插件 BFF） | 本仓库是 dsh 的 fork 整合包，自研能力本就以第一方包整合；BFF 吸收上游协议变动 | 改 dsh 核心源码（升级冲突）；App 直连原生 API（协议面大且漂移） |
| ADR-8 | **定时任务与网页任务看板合二为一**（看板 host 化，v2 新增） | 现有看板 cron 是浏览器标签页定时器、dsh schedule 插件是会话内提醒，都不能「PC 侧可靠定时」；看板拆 host+client 双包后，网页与手机共用同一台账与调度器 | 手机插件自建独立 cron（两套调度器、任务分裂）；维持浏览器调度（网页不开就不跑） |
| ADR-9 | **App 不直连 dsh 原生 `/api`**（v2 新增） | 原生 `/api` 有信任围栏（Host 头须 loopback/`--trusted-host` 名单 + Origin 校验），穿透域名会被拒；52 方法全量协议面暴露给 App 风险大 | 直连 + 启动参数加信任域名（域名变更要改启动配置，不可维护） |

## 6. 功能模块设计

### 6.1 模块总览

```
DSH 遥控器（安卓）
├── 连接模块     —— 穿透域名/口令/工作区配置、登录换 Cookie、心跳、自动重连
├── 任务模块     —— 文本下发、附件上下文、会话事件流渲染、远程审批/提问应答
├── 会话模块     —— 会话列表、状态筛选、历史详情、resume/fork
├── 产物模块     —— Markdown / 代码高亮 / Web 页面预览
├── 定时模块     —— 任务看板镜像（host 化看板的定时任务创建/查看/启停）
├── 推送模块     —— 下行 WS 长连 + 关键节点通知 + 断线补拉
└── 设置模块     —— 模型/provider、工作区、推送开关、关于
```

### 6.2 功能细节

#### 6.2.1 连接模块

- **配置项**：`穿透域名(baseUrl)`、`门禁口令(password)`、`默认工作区路径`、`模型 provider/model`。
- **首次连接**：`GET /api/mobile/info` 校验 protocolVersion 与连通性 → `POST /login`
  用口令换取会话 Cookie → `host.describe` 读取 host 状态。
- **保活**：App 存活期间维持事件流长连接；网络切换（WiFi↔流量）自动重连；
  401/Cookie 过期自动用存储口令重登。
- **状态指示**：连接断开时全局红色横条提示 + 重连中动画；重连成功后自动补齐未读事件。

#### 6.2.2 任务模块

- 输入框支持：纯文本任务描述。
- 附件上下文：照片（拍照/相册）以 base64 image part 随 `session.prompt` 内联携带
  （源码已核实支持，无需独立上传端点）。
- 发送后立即进入会话流视图，实时展示：
  - AI 文本回复（流式）
  - 工具调用卡片（工具名 + 参数摘要 + 结果摘要）
  - 子 Agent 委托提示
  - 产物出现标记
- **远程审批/提问卡**（v2 新增）：agent 等待工具权限（`approval/requested`）或向用户提问
  （`question/requested`）时插入可操作卡片——审批卡「允许一次 / 拒绝」、提问卡选项作答，
  应答走 `POST /api/mobile/respond`；待办在断线重连后由 host 按稳定 rpcId 重放，不会丢失。
- 任务完成判定：`turn/end{reason:'completed'}` + 会话 `running=false` 后收起进度条
  （失败 = `turn/end{reason:'error'}` 或 `host/agent-error`）。

#### 6.2.3 会话模块（任务中心）

- 会话列表：按最后活跃倒序，展示摘要（首条消息/自动摘要）、状态徽标（运行中/完成/失败/暂停）、时间。
- 筛选：全部 / 运行中 / 已完成 / 失败。
- 详情页：完整事件流回放；支持 **resume**（继续对话）与 **fork**（基于历史分叉新会话）。
- 删除会话（可选，操作前二次确认）。

#### 6.2.4 产物模块

- 识别会话事件中的产物类型并渲染：
  - **Markdown 文档**：标题、列表、表格、图片。
  - **代码**：语言识别 + 高亮 + 行号 + 复制按钮。
  - **Web 页面**：内置 WebView 全屏预览。
- 产物卡片化展示，点击进入全屏页。

#### 6.2.5 定时模块（任务看板镜像）

> v2 重定：dsh 的 `schedule` 插件是会话内提醒（非 cron、会话不活跃即挂起），
> 网页任务看板的 cron 是浏览器标签页定时器（网页不开就不跑），均不满足需求；
> 已定案将任务看板 host 化（dsh 仓库 `docs/工作区/任务看板host化.md`），
> 本模块镜像 host 化后的看板台账。

- 数据源：`task-board.list`（经 `/api/mobile/rpc`）+ `taskboard` 事件流标签的变更推送。
- 列表：筛选出带 `schedule` 的任务，展示标题、cron 表达式（转人话描述）、
  启用状态、下次触发时间、最近执行结果。
- 创建：任务标题 + 任务指令（prompt）+ 5 段 cron 表达式（带校验与常用预设）+
  可选钉住目标（工作区 / agent 预设 / 权限）。
- 操作：启用/停用、编辑、删除（确认）、手动「立即执行」。
- 说明：调度在 PC host 进程执行（浏览器与手机都不需要在线）；
  App 只做镜像与增删改，本地缓存可随时清空。

#### 6.2.6 推送模块

- **通道**：App 与 dsh 之间的单条下行 WebSocket（`/api/mobile/events`）承担推送，
  不引入第三方推送 SDK。
- **触发点**（事件流帧 → 手机本地通知）：
  - 任务完成：`turn/end{reason:'completed'}` 且会话转 `running=false`
  - 任务失败/异常：`turn/end{reason:'error'}` / `host/agent-error`
  - **需要用户操作**：`approval/requested`（agent 等权限）/ `question/requested`（agent 提问）——
    高优先级通知，任务在等人
  - 定时任务被触发并开始执行（`taskboard` 流标签 + 对应会话事件）
  - 长时间运行任务的关键节点（可选）
- **本地通知样式**：标题 = 会话摘要，正文 = 状态 + 时间戳；点击通知跳转对应会话详情；
  审批/提问通知点击直达应答卡。
- **后台策略**：引导用户加入电池白名单；前台活跃时直接弹通知，后台依赖长连接存活。
- **断线补偿**（v2 修正）：mux 流的按序号增量补拉官方未实现；App 回到前台后的补偿 =
  重开事件流 + 对活跃会话 `session.history` 拉尾页 + 按 `seq` 去重缝合，
  对补偿期间识别出的「完成/失败/待审批」补发通知（去重）。

#### 6.2.7 设置模块

- 连接配置（域名/口令/工作区/模型）。
- 沙箱策略展示（只读/工作区写入/完全访问 —— 来自 dsh settings，App 仅展示与转发）。
- 推送开关（总开关 + 各类事件开关）。
- 数据管理：清空本地缓存（不影响 PC 侧会话）。
- 关于：版本号、dsh 连接信息。

## 7. UI 设计

### 7.1 设计语言

- **风格**：简洁、清爽，参考 Trae 移动端"操作集中在首页、信息层级清晰"的顺手感；整体使用浅色为主、深色适配，玻璃拟态质感点缀（毛玻璃卡片、半透明导航栏）。
- **布局原则**：
  - 单列流式布局，避免强分栏。
  - 卡片内滚动（列表项内部不整页滚动）。
  - 按钮尺寸/圆角/位置全 App 统一。
  - 空态、加载态、错误态齐全（禁止空白屏）。
- **中文为主**，错误提示用中文人话表述，不给用户看内部异常堆栈。

### 7.2 信息架构（底部 3 Tab）

| Tab | 名称 | 内容 |
|---|---|---|
| 1 | **任务**（首页） | 会话流区（默认当前/最近会话）+ 底部输入栏；新任务直接在此发起 |
| 2 | **历史** | 会话列表 + 筛选 + 进入详情/resume/fork |
| 3 | **我的** | 连接状态卡片、定时任务入口、模型设置、推送开关、关于 |

### 7.3 页面规格

#### 7.3.1 任务页（首页）

```
┌────────────────────────────────┐
│ [连接状态条]  ●在线 dsh@home     │  ← 绿色=在线 / 红色=断开(自动重连)

```

- 新会话：无历史时主体显示引导文案 + 示例指令；有历史时默认展示最近一次会话。
- 输入框聚焦时自动展开，支持快捷指令 `/resume`、`/fork`、`/schedule` 联想。

#### 7.3.2 历史页

- 列表行：摘要（1 行截断）+ 状态徽标 + 相对时间。
- 右上角筛选下拉（全部/运行中/已完成/失败）。
- 点击行 → 会话详情页（同任务页布局，顶部显示会话标识与操作按钮：续聊 / 分叉 / 删除）。

#### 7.3.3 我的页

- 连接状态卡片：域名、状态、上次握手时间，点击进入连接配置。
- 定时任务入口：列表页 + 新建页（cron 输入 + 指令输入）。
- 设置分组：连接 / 模型 / 推送 / 数据 / 关于。

### 7.4 关键交互细节

| 交互 | 规格 |
|---|---|
| 发送任务 | 输入框回车/发送按钮；发送后立即清空输入并聚焦会话流 |
| 流式渲染 | AI 文本逐段上屏；工具调用以卡片插入，不打断消息流 |
| 产物预览 | 卡片点击全屏；Web 预览页支持返回/刷新/打开外部浏览器 |
| 断开重连 | 全局顶部红色横条 + "重连中"动画；成功自动消失 |
| 通知点击 | 跳转对应会话详情页并定位到最新事件 |
| 二次确认 | 删除会话、删除定时任务时弹确认对话框 |

### 7.5 主题

- 浅色主题为默认，跟随系统深色模式（Material 3 Dynamic Color 可关闭）。
- 强调色：单一品牌色（建议 dsh 风格深蓝/青），用于按钮、链接、进行中状态。
- 状态色：运行中=强调色、完成=绿色、失败=红色、暂停=灰色。
- 字体：系统默认，中文回退无需内置字体。

  id: string
  summary: string
  status: enum(running|idle|error|paused)

  lastSeq: int         # 已缝合到的事件序号（用于重连后去重/找洞）

  id: string
  title: string
  prompt: string       # 任务指令

  enabled: bool        # 以 schedule 是否存在表达启停
  nextRunAt: datetime?
  lastExecution: { sessionId, startedAt, endedAt, result }?

  pushEnabled: bool
  pushEventFlags: { taskDone: bool, taskError: bool, needAction: bool, scheduleStart: bool }
  batteryWhitelistHinted: bool

## 9. 非功能需求

### 9.1 安全

- 门禁口令与会话 Cookie 存 flutter_secure_storage（Android Keystore），不以明文落盘。
- 仅 HTTPS 连接（内网穿透需启用 TLS；App 禁止明文 HTTP 回退）。
- 证书 TOFU 校验：首次连接记录证书指纹（自签/自定义证书均可），之后每次比对，
  指纹变化即告警阻断（防中间人替换）。
- 不记录/不上传任何日志到第三方；崩溃日志可选本地留存；口令不进日志。

### 9.2 性能

- 事件流渲染采用增量更新，长会话不一次性渲染全部历史。
- 产物预览按需加载；Web 预览用独立 WebView 进程。
- 冷启动 < 2s，任务流切换无卡顿（目标帧率 60fps）。

### 9.3 可靠性

- 网络断开自动重连（指数退避，上限 30s）；401 自动重登。
- 会话事件以 dsh 侧为准；重连后重开事件流 + 拉会话尾页 + 按 seq 去重缝合
  （mux 增量补拉官方未实现，不依赖）。
- App 崩溃不影响 PC 任务继续执行（任务在 PC 侧运行）。

### 9.4 保活

- 前台：正常使用。
- 后台：长连接 + 电池白名单引导；Android 13+ 使用前台服务通知常驻（可选，避免被系统杀死）。
- 定时任务依赖 PC 侧 schedule，与 App 存活无关。

### 9.5 兼容性

- Android 9（API 28）及以上（Flutter 默认下限可按实际调）。
- 横竖屏自适应（默认竖屏，Web 预览支持横屏）。

## 10. 分期路线

| 阶段 | 目标 | 交付内容 | 前置依赖（dsh 侧） |
|---|---|---|---|
| **P1 连通** | 跑通手机→dsh 通信 | 连接配置页、`/api/mobile/info` 校验 + 登录换 Cookie、发一条 prompt、收到回复 | 手机遥控插件 P1 端点（info/rpc/events） |
| **P2 会话流** | Trae 式流式体验 | 事件流订阅、流式渲染、工具调用卡、**审批/提问卡**、会话列表、resume/fork、断线缝合 | 同上（respond 端点） |
| **P3 产物+定时** | 完整可用 | 产物预览（文档/代码/Web）、定时任务管理 UI（看板镜像） | fs 端点；**任务看板 host 化完成** |
| **P4 推送** | 后台通知 | 长连推送、本地通知、电池白名单引导、断线补偿 | taskboard 事件标签 |

> 实施顺序（dsh 侧先行）：①任务看板 host 化 → ②手机遥控插件 → ③App P1→P4。
