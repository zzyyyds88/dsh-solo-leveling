# DSH 升级适配指南（AI Agent 用）

> 面向 **opencode / Claude Code 等任意 AI Agent** 执行 DSH 官方升级时的强制规则与步骤。
> 本仓库全部插件已脱离上游、归本仓库所有；但 **DSH 官方（`@deepseek-ai/*`）升级时**，
> 本仓库的「同包名 fork」与「针对旧版限制的适配层」必须按本指南适配，否则会静默跑旧代码。

## 0. 一条铁律（每次升级先读这条）

**如果官方新版已经实现了与本仓库改动相同的功能 → 优先用官方，删掉/停用本仓库对应的 fork 或适配层。**

- 判断依据是**官方新版源码**，不是 release notes 的字面描述。
- 只有官方**没做、或官方做的方式不满足需求**时，才保留本仓库的 fork / 适配层。
- 保留时也必须把 fork **重 base 到新版官方源码**，不能继续用旧版源码。

## 3. 升级适配流程（AI Agent 逐步执行）

1. **读官方 release notes + 源码 diff**（对照 `packages/` 新旧结构；rc.7 已重组为域目录）。
2. **跑版本守卫**识别过期 fork：
   ```bash
   DSH_HOME=/root/.dsh bash scripts/check-fork-versions.sh   # 正式
   DSH_HOME=test-envs/test-env-1 bash scripts/check-fork-versions.sh  # 测试
   ```
   `[STALE]` 的 fork 即「旧版源码还在跑」。
3. **逐项核对 §2**：官方是否已实现同功能。
   - 已官方化 → **弃用本仓库 fork/适配层**（从 profile 移除 + 收敛 patch 行），改用官方。
   - 未官方化 → **重 base**：把 fork 源码更新到新版官方源码 + 重打补丁（补丁对照各项目
     `定制记录/本次diff.patch`），版本号改成 `<新版>-local.N+1`。
4. **测试环境验证**（重装到 test-env + `verify.sh`/`check-fork-versions.sh` 全绿）。
5. **用户验收后**正式重装：`bash scripts/formal-reinstall.sh --rebuild`。
6. 同步更新本指南 §1 基线、AGENTS.md「关键事实」、PLUGINS.md。

## 4. 版本守卫（防静默过期）

`scripts/check-fork-versions.sh` 比对「全局 DSH 版本」与「每个 fork 的 built-against 版本
（`-local.N` 前缀）」，不一致即 `[STALE]` 并以非 0 退出。把它接进升级/重装前的前置检查，
避免「DSH 已升级、fork 还是旧版」的静默问题。

## 5. 回退

- 弃用 fork 前先备份：profile 里 fork 目录 cp 成 `.bak`（安装脚本会自动 `.bak` 备份）。
- 回退 = 把 `.bak` 拷回 + 收敛 patch 行 + 重启（用户执行）。
