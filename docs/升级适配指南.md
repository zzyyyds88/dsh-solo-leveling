# DSH 升级适配指南（AI Agent 用）

> 面向 **任意 AI Agent** 执行 DSH 官方升级时的强制规则与步骤。
> 本仓库全部插件已脱离上游、归本仓库所有；但 **DSH 官方（`@deepseek-ai/*`）升级时**，
> 本仓库的「同包名 fork」与「针对旧版限制的适配层」必须按本指南适配，否则会静默跑旧代码。

## 0. 一条铁律（每次升级先读这条）

**如果官方新版已经实现了与本仓库改动相同的功能 → 优先用官方，删掉/停用本仓库对应的 fork 或适配层。**

- 判断依据是**官方新版源码**，不是 release notes 的字面描述。
- 只有官方**没做、或官方做的方式不满足需求**时，才保留本仓库的 fork / 适配层。
- 保留时也必须把 fork **重 base 到新版官方源码**，不能继续用旧版源码。

## 2. 本仓库对 DSH 的全部改动清单（升级时逐项核对）

### 2.2 针对 rc.6 限制的适配层（最可能被 rc.7 官方取代，优先核实弃用）

| 适配层 | 作用 | rc.7 处置建议 |
|---|---|---|
| `dsh-web-ui-settings`（组卡片 + rc.6 兼容 bridge + `allowlist.ts`） | 绕过 rc.6 硬编码 `WEB_SETTINGS_NAMESPACES` 白名单，让 family 插件卡片可用 | rc.7「各插件可自行注册设置卡片」若开放 → **弃用 bridge/allowlist**，组卡片视需要保留 |

`__ModuleLoader__` 格式变化时需要重建。

## 3. 升级适配流程（AI Agent 逐步执行）

1. **读官方 release notes + 源码 diff**（对照 `packages/` 新旧结构；rc.7 已重组为域目录）。
2. **逐项核对 §2**：官方是否已实现同功能。
   - 已官方化 → **弃用本仓库对应的 fork/适配层**，改用官方。
   - 未官方化 → **重 base**：把对应包源码更新到新版官方源码 + 重打补丁。
3. **本地验证**（打包后独立实例逐项核对全绿）。
4. **用户验收后**正式重装：`npm i -g ./dist/npm/*.tgz`（用户在 SSH 终端执行）。
5. 同步更新本指南 §1 基线、AGENTS.md「关键事实」、PLUGINS.md。

## 4. 防静默过期

整合包自维护基线，DSH 官方升级后要重 base 到新版源码（§3），避免「DSH 已升级、
整合包还是旧版源码」的静默问题。升级前先读 §0 铁律。

## 5. 回退

- 弃用 fork 前先 git 提交当前状态（可 revert）。
- 回退 = git revert + 重新 `pnpm run build` + 重新打包（用户执行）。
