## 2026-08-16 —— dsh-defaults 统一插件（合并两个旧项目）

### 目标

把「修改默认工作目录」与「思考强度与重试默认值」两个补丁项目合并为**一个插件**：
默认工作目录与默认重试次数由用户在「设置 → 插件 → 默认值」中自行配置；
思考强度菜单保持 fork 内建默认档位（不进设置页，composer 对话框直接可调）。

### 交付物

| 交付物 | 位置 | 说明 |
|---|---|---|
| `dsh-defaults` 宿主插件 | `packages/dsh-defaults/lib/index.js` | 注册 `dsh-defaults` 命名空间（手写 ESM，源码即产物） |
| `dsh-client-ui-defaults` 前端插件 | `packages/dsh-client-ui-defaults/lib/client.js` | 「默认值」设置标签页（手写 bundle） |
| `dsh-host-directory-picker-browse` fork | `../定制插件化改造/packages/dsh-host-directory-picker-browse/` | `list()` 无路径时读 `defaultWorkingDirectory`（新 fork，从 upstream 源码建） |
| `dsh-llm-pi-ai` fork 扩展 | `../定制插件化改造/packages/dsh-llm-pi-ai/` | 重试默认值兜底 + `settings/updated` 变更监听 |
| `dsh-host-apiproxy` fork 扩展 | `../定制插件化改造/packages/dsh-host-apiproxy/` | `exposedNamespaces()` 增加 `dsh-defaults` |
| 安装/验证脚本 | `install-defaults-plugin.mjs` / `build.sh` / `install-to-*.sh` / `verify-defaults.mjs` | 幂等安装 + 黑盒验证（9 项断言） |

### 设置命名空间

```yaml
dsh-defaults:
  defaultWorkingDirectory: ""   # 空 = 官方行为（host 主目录）
  defaultRetryCount: 10         # 未声明 retryPolicy 的第三方供应商的默认重试次数
```

### 关键实现细节与踩坑

1. **重试兜底必须带 `mode`**：`resolveRetryPolicy({maxRetries: N})` 会抛
   `retryPolicy.mode must be "normal" or "always"`。兜底对象必须写全
   `{ mode: 'normal', maxRetries: N }`（旧 `patch-retry-policy.py` 之所以没踩，
   是因为它把整段 YAML（含 mode）写进了供应商配置）。
2. **重试变更监听 `settings/updated` 而非 `settings/document-updated`**：
   `SettingsProvider.update()` 流程为 `persist → bumpRevision → commit`，
   `bumpRevision`（发 `document-updated`）先于 `commit`（替换 resolved 值），
   监听 `document-updated` 会读到旧值 → `ensureRegistrationFacts` 判定 facts
   未变 → 不重新注册（dsh-llm 在注册时捕获 retryPolicy，必须重新注册才生效）。
   `settings/updated` 在 `commit` 之后同步发出，值已刷新。
3. **目录选择器走 host 端 fork**：`list()` 每请求实时读命名空间，改设置即时生效；
   旧 client 端 fork（构建期注入）退役，安装脚本移除后 Loader 回退官方版。
4. **profile 加载顺序**：`dsh-defaults` 命名空间在 `llm-pi-ai` 之后挂载时，
   重试兜底在首次注册时读不到命名空间属正常；`settings/updated` 监听会在
   文档加载/首次写入时补触发重新注册。

## 2026-08-16（二）—— 重试全局生效 + 配置入口改「插件配置」卡片

### 需求（用户验收反馈）

1. 默认重试次数要对**所有供应商**生效（包括内置 DeepSeek 供应商），不只是第三方。
2. 配置入口改为「设置 → 插件 → 插件配置」区的**独立卡片**（样式同官方「网页搜索」
   卡片），而不是独立标签页。

### 改动

| 交付物 | 说明 |
|---|---|
| `dsh-llm` fork（新增） | `prepareRoutes` 注册兜底：providerRetryPolicy 为 undefined 的 adapter 用 `defaultRetryCount`（全局最后一环） |
| `dsh-llm-deepseek` fork（新增） | 内置 DeepSeek：`resolveAdapterOptions` 中 `config.retryPolicy ?? {mode:'normal', maxRetries: defaultRetryCount}`；`options()` memo 键含 defaults 身份；监听 `settings/updated` 重新注册 |
| `dsh-client-ui-defaults` 重写 | 注册 `settings.plugin.item` 卡片（可展开、保存/放弃、未保存标记），移除 `settings.plugins.tab` 标签页注册 |
| 安装脚本 | fork 列表加入 `dsh-llm`、`dsh-llm-deepseek`；修复 `install-defaults-plugin.mjs` 幂等检查（只查第一个 insert 块导致重复追加 `ui-dsh-defaults` → 启动报 duplicate loader entry id） |

### 关键点

- llm-deepseek 的 `providerRetryPolicy` 返回**解析后的具体值**（未写时也是官方默认），
  所以 dsh-llm 层兜底（`?? fallback`）对它不生效——必须 fork llm-deepseek 在
  解析处兜底。三层兜底（pi-ai / deepseek / llm）覆盖全部供应商，互不冲突。
- `settings/updated`（commit 事件，resolved 已替换）而非 `settings/document-updated`
  （bumpRevision 先于 commit，读到旧值）——同 pi-ai fork 的经验，llm-deepseek 同样处理。

### 验证（test-env，端口 3090）

- harness：dsh-llm 兜底（未声明→defaults 值 / 显式→优先 / 无设置→官方默认）；
  llm-deepseek `resolveAdapterOptions` 四场景（8 / 3 / 官方 / 0）全过。
- 实例：verify-defaults.mjs 9 项全过；改 defaultRetryCount 写入/还原无错误；
  deepseek-official + tokenrhythm 均注册、强度菜单正常；卡片 bundle 含
  `settings.plugin.item` 注册。
